把 SSRF 的排查过程整理成一份可以照着走的清单，重点是**别只盯着 URL 参数**。

<!--more-->

## 一、先找入口

SSRF 的本质是服务端替你发请求。所以任何"服务端会去取一个地址"的功能都是候选：

- 图片/文件 URL 导入、远程头像拉取
- Webhook 配置、回调地址填写
- PDF / 截图 / 网页转码服务
- RSS 订阅、站点地图抓取
- 富文本编辑器的"从链接插入图片"
- 各种 `url=`、`target=`、`src=`、`domain=`、`callback=` 参数

> 经验：先看请求体里有没有长得像 URL 的值，再看有没有 `http` 开头的字符串，最后才去猜参数名。

## 二、判断回显类型

| 类型 | 判断方式 | 利用难度 |
|---|---|---|
| 完全回显 | 响应里直接有目标页面内容 | 最低 |
| 半回显 | 只返回状态码 / 长度 / 标题 | 中 |
| 盲 SSRF | 什么都看不到 | 高（需带外） |

## 三、协议与内网探测

确认能发请求后，先画内网拓扑：

```text
http://127.0.0.1:80
http://127.0.0.1:6379      # Redis
http://127.0.0.1:3306      # MySQL
http://169.254.169.254/    # 云元数据
file:///etc/passwd
gopher://127.0.0.1:6379/_INFO
dict://127.0.0.1:11211/stat
```

云环境优先试元数据接口，很多实际危害都是从这里打出来的。

## 四、绕过手法

当目标做了黑名单过滤时，依次尝试：

1. **进制/编码变换**：`127.0.0.1` → `2130706433`、`0177.0.0.1`、`0x7f.1`
2. **DNS 重绑定**：用自己的域名解析到内网 IP，绕过基于字面量的校验
3. **302 跳转**：外网 URL 返回 302 指向内网，看是否跟随
4. **URL 解析歧义**：`http://evil.com@127.0.0.1/`、`http://127.0.0.1#@evil.com`
5. **短链接**：借第三方跳转服务

## 五、修复建议

- 白名单域名 + 解析后校验 IP（**先解析再校验，防 DNS 重绑定**）
- 禁止跟随重定向，或对每一跳重新校验
- 禁用 `file://`、`gopher://`、`dict://` 等非 HTTP 协议
- 出网流量走统一代理，默认拒绝内网段
